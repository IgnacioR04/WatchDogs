# WATCHDOG V4 migration risk register

Baseline: 2026-08-09. Severity follows the [master plan](MASTER_PLAN.md): P0 stops the affected phase; P1 blocks the phase gate; P2 needs explicit debt/orchestrator acceptance; P3 is non-blocking polish.

Name similarity alone could join different people and misattribute financial activity. | Canonical UUIDs, verified external IDs, explainable candidates, explicit ambiguity, audited manual overrides; never auto-merge on fuzzy score alone; adversarial homonym tests and Data Quality approval. | P3 | Open/known |

## Gate interpretation

P0 does not resolve these migration risks; it makes them explicit and assigns proof to later phases. R1 and R13 are stop-rule risks: any design that can falsely attribute real financial activity to a person must be rejected before implementation/merge. R2–R12 and R14 remain gate-blocking at the phases listed unless their acceptance evidence exists.
